#### 3. URL malformée (double `.vercel.app`)
- L'URL collée contenait `...vercel.app/.vercel.app/api/shopify/auth` → 404 immédiat
- Fix : utiliser l'URL stable sans duplication

#### 4. Shopify Partners — nouveau dashboard
- Les URLs OAuth sont dans **Versions** (pas App setup), dans la section Configuration de la version draft

### Déploiement CLI Shopify

Problèmes rencontrés :
1. **Mauvais compte CLI** ("You are not a member of the requested organization") → `shopify auth logout` + `shopify auth login`
2. **DNS bloqué** (`getaddrinfo ENOTFOUND app.shopify.com`) → la box internet (192.168.1.1 `dev.opt`) ne résolvait pas `app.shopify.com`. Fix : DNS changé en `8.8.8.8` / `8.8.4.4` dans les paramètres IPv4 Windows

Première version déployée : **hijabtryonapp-6**

### Bugs rencontrés et fixes

#### 1. ERR_FAILED CORS
- Cause : Vercel Deployment Protection activée + headers CORS manquants
- Fix 1 : Désactiver Vercel Deployment Protection
- Fix 2 : Ajouter dans `next.config.js` :
  ```js
  async headers() {
    return [{ source: '/api/shopify/:path*', headers: [CORS_HEADERS] }];
  }
  ```

#### 2. URL protocole-relative `//cdn.shopify.com/...`
- Shopify CDN renvoie des URLs sans protocole (`//cdn.shopify.com/...`)
- Fix Liquid : `data-product-image="https:{{ product.featured_image | image_url: width: 1024 }}"`
- Fix backend : `const absoluteUrl = url.startsWith('//') ? 'https:' + url : url;`

#### 3. Block setting type `url` → `text`
- `type: "url"` dans le schema Liquid stockait le chemin de la page au lieu de l'URL externe
- Fix : changé en `type: "text"` avec default `https://hijabtryon.com`

#### 4. TypeScript checker sur `extensions/`
- `tsconfig.json` incluait les fichiers JS du widget → erreurs TypeScript
- Fix : ajout de `"extensions"` dans le tableau `exclude` de `tsconfig.json`

### Résultat Phase 2
Génération try-on confirmée fonctionnelle end-to-end : upload photo → modal → résultat image générée.

## UX — Barre de progression + téléchargement

### Téléchargement direct
- Problème : lien direct Shopify CDN = cross-origin, le navigateur refusait le téléchargement
- Fix : téléchargement via blob URL (`fetch → blob → URL.createObjectURL → <a>.click()`)

### Barre de progression — historique des tentatives

| Version déployée | Approche | Résultat |
|-----------------|----------|----------|
| setInterval 100ms/0.3% | `style.width` sur div enfant | Barre vide |
| CSS animation + classe `.is-loading` | `@keyframes` dans CSS file | Barre vide |
| Injection dynamique `@keyframes` | `document.head.appendChild(style)` | Barre vide (CSP Shopify) |
| setInterval 500ms/3% | `style.setProperty('width', ...)` sur div enfant | Barre vide |
| **Gradient single-element** ✅ | `style.setProperty('background', gradient)` | **FONCTIONNE** |

**Cause racine** : Le CSS du thème Shopify override les `width` des divs enfants même avec inline styles. La CSP Shopify bloque l'injection de `@keyframes`.

**Solution finale** (hijabtryonapp-14) :
```js
// Un seul div, on change le stop du gradient :
progressBar.style.setProperty(
  'background',
  'linear-gradient(to right, #7c3aed ' + pct + '%, #e5e7eb ' + pct + '%)'
);
```

**Diagnostic clé** : ajout d'un compteur texte `<span id="hijab-tryon-pct">` qui confirmait que le JS s'exécutait bien (le texte incrémentait : 3%, 6%, 12%…) mais la barre restait invisible — prouvant un problème de rendu CSS, pas de JS.

### Partie B — Système de Crédits Clients

#### Fonctionnalités
| Paramètre configurable | Défaut | Description |
|------------------------|--------|-------------|
| `creditsPerCustomer` | 4 | Try-ons offerts par nouveau client |
| `allowAnonymousCredits` | true | Visiteurs non connectés autorisés |
| `minPurchaseForReset` | null | Montant min. d'achat pour reset (null = tout achat) |

#### Identification clients
- Connecté : `window.Shopify.customerId`
- Anonyme : UUID `localStorage` (clé `hijab_tryon_uid`)

#### Cycle de vie
1. Première visite → upsert crédit avec `creditsPerCustomer`
2. Génération réussie → décrémente de 1
3. `orders/paid` webhook → reset si montant ≥ seuil

#### Nouveaux modèles Prisma
```prisma
// Ajoutés à ShopifyStore :
creditsPerCustomer    Int      @default(4)
allowAnonymousCredits Boolean  @default(true)
minPurchaseForReset   Decimal?

// Nouveau modèle :
model ShopifyCustomerCredit {
  storeId    String
  customerId String
  isAnonymous Boolean @default(false)
  credits    Int
  @@unique([storeId, customerId])
}
```
Appliqué via `npx prisma db push`.

#### Nouvelles routes API
| Méthode | Route | Description |
|---------|-------|-------------|
| GET | `/api/shopify/tryon/credits` | Récupère/crée crédits client |
| POST | `/api/shopify/tryon/credits/deduct` | Déduit 1 crédit |
| GET | `/api/shopify/dashboard/credits` | Settings + liste clients |
| PATCH | `/api/shopify/dashboard/credits` | Màj settings ou crédits manuels |

#### Widget JS — comportement crédits
```
Load → GET credits → disable bouton si 0
Modal → GET credits → affiche compteur (rouge si ≤1)
Générer → check local → POST tryon → si succès → POST deduct → màj compteur
```

#### Dashboard marchand (`/shopify-dashboard`)
- Formulaire `CreditSettingsForm` (3 champs + Save)
- Table crédits clients (customerId tronqué, badge Anonyme/Connecté, crédits, dernière activité)
